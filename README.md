# VC Recorder — бот для записи голосовых и видеочатов в Telegram

Связка из обычного бота (витрина, оплата, панель управления) и пула
юзербот-аккаунтов (заходят в голосовые/видеочаты групп и записывают их).
Премиум продаётся подпиской за Telegram Stars (автопродление раз в 30 дней)
либо разовой покупкой периода через крипту (**CryptoBot**) или карту
(**ЮKassa**).

## Как это устроено

Бот и юзербот-пул — это **два независимых процесса**, которые общаются
только через общую базу данных. Юзербот-процесс никогда не импортирует
код бота и наоборот — зависший ffmpeg, упавший из-за лимитов Telegram
воркер или зависание одного аккаунта не положит бота с платежами, и
наоборот.

```
┌────────────────┐        aiogram (Bot API)        ┌───────────────────┐
│  Пользователь   │◄───────────────────────────────►│  run_bot.py        │
│  (личка с ботом)│   меню, тарифы, оплата, файлы    │  • меню/оплата      │
└────────────────┘                                   │  • панель /workers:  │
                                                       │    вход по номеру/  │
┌────────────────┐                                    │    коду/паролю      │
│     Админ       │◄──────────────────────────────────│  • приём вебхуков   │
│                 │   панель управления пулом          │  • outbox: рассылка │
└────────────────┘                                     │    готовых записей  │
                          общая БД (SQLite/Postgres)    │  • автоочистка       │
                     ┌───────────────────────────────►│                    │
                     │                                └───────────────────┘
┌────────────────┐   │ join_chat по ссылке, /record,   ┌───────────────────┐
│  Группа Telegram│◄──┴  /stoprecord                     │  run_userbot.py    │
│  (голосовой чат)│   заходит в звонок, пишет трек на    │  пул воркеров:      │
└────────────────┘   каждого участника отдельно         │  N × (Pyrogram +    │
                                                          │  pytgcalls),         │
                                                          │  reconcile-цикл      │
                                                          └───────────────────┘
```

Юзербот-процесс только пишет в базу: статус записи (`status=done`,
`file_path=...`), статус каждого воркера, результат заявок на смену
профиля. Бот-процесс опрашивает базу и реагирует: рассылает готовые
записи, показывает актуальный статус пула. Ни один процесс не держит
прямых ссылок на объекты другого — это касается и живого Pyrogram-
соединения воркера: панель в боте никогда не обращается к нему напрямую,
даже для смены имени/био/фото (см. «Пул аккаунтов» ниже).

## Возможности

- Запись голосовых чатов (аудио), по одной дорожке на участника →
  автоматический микс в один файл + опционально ZIP с отдельными дорожками
  (полезно для монтажа/подкастов)
- Запись видеочатов — все камеры сводятся в один общий грид-видеоряд
  (как в Zoom/Meet gallery view) через ffmpeg `xstack`: разные разрешения
  приводятся к общему размеру с сохранением пропорций, участник, у которого
  видео закончилось раньше остальных, замораживается на последнем кадре
  вместо обрезки всего ролика. Звук — общий микс всех участников, включая
  тех, у кого камера была выключена. Отдельные ракурсы каждого участника
  дополнительно доступны ZIP-архивом
- Подписка Telegram Stars с автопродлением каждые 30 дней (нативный
  механизм Bot API) — плюс отмена в любой момент прямо в боте
- Разовая покупка периода (1/3/12 месяцев) криптовалютой через CryptoBot
  или картой через ЮKassa (вебхуки с проверкой подписи/IP + запасной
  вариант «✅ Я оплатил(а)» без вебхука)
- Промокоды (`/addpromo` у админа) и реферальная программа — бонусные дни
  Премиума за приглашённых друзей и их первую оплату
- Лимиты бесплатного/премиум тарифа (минуты записи, число чатов, срок
  хранения) — настраиваются в `.env`
- Автоудаление записей по истечении срока хранения
- Личный кабинет, история записей, расширенная админка (`/stats`, `/find`,
  `/grant`, `/ban`, `/unban`, `/addpromo`, `/broadcast`)
- Пул аккаунтов-воркеров с панелью управления прямо в боте (`/workers`,
  админам) — добавление обычным входом (номер → код → пароль 2FA), список
  со статусами, включение/отключение, удаление, редактирование профиля
  (имя/био/фото). Новый или отключённый аккаунт подхватывается фоновым
  циклом без перезапуска процесса
- Бот и юзербот-пул работают как два независимых процесса (см. диаграмму выше)
- Хранение записей — локальный диск по умолчанию, либо любое
  S3-совместимое хранилище (AWS S3, MinIO, Cloudflare R2, Backblaze B2):
  файл загружается сразу после сведения, боту для доставки достаточно
  presigned-ссылки — повторной закачки через сам процесс не происходит

## ⚠️ Про согласие на запись — прочитайте перед запуском

Бот **всегда** присылает в группу сообщение о том, что запись началась
(`config.ANNOUNCE_RECORDING`, по умолчанию включено) — participants должны
знать, что разговор записывается. В части юрисдикций запись разговора без
ведома участников незаконна (законы о прослушке/защите персональных
данных). Ответственность за соблюдение местного законодательства лежит на
администраторе группы, который запускает запись, и на операторе бота.
Не отключайте оповещение, если у вас нет своего процесса получения
согласия участников.

## Требования

- Python 3.10+ (для Docker-варианта — не важно, всё уже в образе)
- `ffmpeg` устанавливать отдельно не нужно — `imageio-ffmpeg` в
  requirements.txt ставит вместе с собой полноценный статический бинарник
  (проверено: включает libx264, libopus, aac и фильтры xstack/tpad/amix/apad,
  которые использует сведение дорожек и грид-рендер видео)
- Аккаунты для записи — **отдельные, не личные**: каждый будет виден как
  участник во всех звонках, которые записывает, а активная автоматика на
  аккаунте — это некоторый риск ограничений со стороны Telegram. Добавляются
  через панель в боте (см. «Пул аккаунтов» ниже) — tdata и другие способы
  импорта готовой сессии не поддерживаются: только обычный вход по номеру

## Установка

### 1. Получите ключи

| Что | Где |
|---|---|
| `BOT_TOKEN` | [@BotFather](https://t.me/BotFather) → `/newbot` |
| `API_ID` / `API_HASH` | [my.telegram.org](https://my.telegram.org) → API development tools |
| `CRYPTOBOT_TOKEN` | [@CryptoBot](https://t.me/CryptoBot) → Crypto Pay → Create App |
| `YOOKASSA_SHOP_ID` / `YOOKASSA_SECRET_KEY` | Личный кабинет ЮKassa → Настройки → API |

### 2. Настройте окружение

```bash
cp .env.example .env
# заполните .env текстовым редактором
```

### 3. Локальный запуск (без Docker)

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# один раз — ключ шифрования сессий воркеров:
python -m database.generate_encryption_key
# впишите вывод в WORKER_ENCRYPTION_KEY в .env

python run.py
```

`run.py` — одна команда, запускает бота и пул воркеров вместе. Под
капотом это по-прежнему два независимых процесса (`run_bot.py` +
`run_userbot.py` как дочерние) — если один упадёт, `run.py` перезапустит
именно его через несколько секунд, второй процесс это не затронет.
Ctrl+C останавливает оба. Если нужно видеть логи каждого процесса в
отдельном окне, их по-прежнему можно запустить и вручную, в двух
терминалах: `python run_bot.py` и `python run_userbot.py`.

Аккаунты для записи добавляются уже после запуска — через `/workers` в
личке с ботом (см. «Пул аккаунтов» ниже), не через .env и не через
отдельный скрипт.

### 4. Через Docker (рекомендуется для продакшена)

```bash
python -m venv .venv && source .venv/bin/activate && pip install cryptography
python -m database.generate_encryption_key   # впишите результат в .env
docker compose up -d --build
```

`docker-compose.yml` запускает `run_bot.py`/`run_userbot.py` как два
настоящих независимых контейнера напрямую — `run.py` там не участвует,
эту роль (перезапуск, изоляция) для Docker уже выполняет сам Compose.

`docker compose` поднимет два контейнера — `bot` и `userbot` — как
независимые сервисы с общим томом `./storage`. Логи каждого отдельно:
`docker compose logs -f bot` / `docker compose logs -f userbot`. Если один
из процессов упадёт (например, юзербот получит временный лимит от
Telegram), `restart: unless-stopped` поднимет обратно только его —
второй продолжит работать без перерыва.

### 5. Подключите вебхуки платёжных систем (необязательно)

Без этого шага оплата всё равно работает — просто пользователь подтверждает
её кнопкой «✅ Я оплатил(а)», а не мгновенно. Чтобы включить мгновенное
подтверждение, разместите бота за HTTPS (например, за Nginx/Caddy или
Cloudflare Tunnel), укажите `PUBLIC_BASE_URL` в `.env` и добавьте:

- **CryptoBot**: My Apps → ваше приложение → Webhooks → укажите
  `{PUBLIC_BASE_URL}/webhooks/cryptobot/{WEBHOOK_SECRET}`
- **ЮKassa**: Настройки → HTTP-уведомления → укажите
  `{PUBLIC_BASE_URL}/webhooks/yookassa/{WEBHOOK_SECRET}`

### 6. S3-хранилище вместо локального диска (необязательно)

По умолчанию записи лежат в `storage/recordings`. Чтобы вместо этого
использовать S3-совместимое хранилище (полезно, если `bot`/`userbot`
когда-нибудь будут жить на разных машинах, или диск контейнера — временный),
укажите в `.env`:

```
S3_ENABLED=true
S3_BUCKET=your-bucket
S3_ACCESS_KEY=...
S3_SECRET_KEY=...
S3_REGION=us-east-1
S3_ENDPOINT_URL=            # пусто для настоящего AWS S3; для MinIO/R2/B2 — их endpoint
```

Файл загружается в бакет сразу после сведения ffmpeg, локальная копия
удаляется. Доставка пользователю идёт по временной (presigned) ссылке —
сам бот файл повторно не скачивает и не загружает.

## Пул аккаунтов

Записывающие аккаунты добавляются и управляются целиком через бота —
`/workers` (только для id из `ADMIN_IDS`):

1. «➕ Добавить аккаунт» → бот просит номер телефона в международном
   формате (`+15551234567`)
2. Приходит код в Telegram/СМС → отправляете его сообщением боту
3. Если на аккаунте включена двухфакторная аутентификация — бот попросит
   пароль от неё
4. Готово — аккаунт появляется в пуле и активируется в течение
   `WORKER_RECONCILE_INTERVAL_SECONDS` (по умолчанию 15 сек), без
   перезапуска процессов

Это обычный вход в Telegram, тот же самый, что при входе в официальное
приложение с нового устройства. Импорт готовой сессии (tdata и подобное)
осознанно не поддерживается.

Из панели по каждому аккаунту доступно:
- статус (активен / отключён / ошибка) и число подключённых чатов из
  `max_chats`
- включение/отключение — отключённый аккаунт перестаёт браться в оборот
  для новых клиентов, но уже идущую запись никто не обрывает
- удаление
- редактирование профиля (имя, био, фото) — заявка на изменение пишется в
  базу и применяется процессом юзербота через уже открытое соединение
  этого аккаунта (бот-процесс никогда не обращается к живому соединению
  напрямую — см. диаграмму архитектуры)

Когда клиент нажимает «➕ Подключить чат», бот сам называет наименее
загруженный активный аккаунт из пула и просит прислать пригласительную
ссылку на группу. Аккаунт заходит в неё сам (`join_chat`) и сразу
регистрирует чат — добавлять его в группу вручную не нужно. Если ссылка
уже не действует или группа требует подтверждения администратора, бот
сообщает об этом прямо, а не оставляет клиента в неведении.

## Использование

В личных сообщениях с ботом: `/start` → меню. Там же — раздел «Пригласить
друзей» (реферальная ссылка) и «У меня промокод» в разделе Премиум.

Реферальная ссылка вида `https://t.me/<бот>?start=ref_<ваш_id>` — если
кто-то перешёл по ней, вы получаете бонусные дни сразу (`REFERRAL_SIGNUP_BONUS_DAYS`)
и ещё больше, когда друг оформит первую оплату (`REFERRAL_PURCHASE_BONUS_DAYS`).

Подключение чата: «➕ Подключить чат» в личке с ботом → прислать
пригласительную ссылку на группу → готово, придёт подтверждение. В самой
группе (после подключения, только для админов группы):

```
/record          — начать запись аудио
/record video    — начать запись аудио + видео
/stoprecord      — остановить, файл придёт в личку инициатору
/status          — идёт ли сейчас запись
/connect         — ручное подключение (если группу уже добавили вручную,
                    без ссылки через бота)
```

Команды администратора бота (id из `ADMIN_IDS` в `.env`):

```
/stats                                            — сводная статистика и выручка по методам оплаты
/find <user_id или @username>                     — карточка пользователя
/grant <user_id> <дней>                           — выдать Премиум вручную
/ban <user_id> / /unban <user_id>                 — бан/разбан (забаненные не получают /broadcast)
/addpromo <CODE> <дней> [макс_активаций] [сгорает_через_дней]  — создать промокод
/broadcast                                        — ответом на сообщение — разослать всем
/workers                                          — открыть панель пула аккаунтов (то же, что кнопка в меню)
```

## Большие файлы

Обычный Bot API не даёт боту отправить файл тяжелее **50 МБ**. Для длинных
записей (особенно видео) либо ограничивайте `PREMIUM_MAX_MINUTES`, либо
разверните [собственный Bot API сервер](https://github.com/tdlib/telegram-bot-api)
(лимит вырастает до 2 ГБ) и укажите его адрес при создании `Bot(...)` в
`bot/loader.py` через параметр `base_url`.

## Статус

Все пункты изначальной дорожной карты реализованы, включая пул аккаунтов
с панелью управления в боте. Каждая фича проверена не только на
компиляцию/импорт, но и функционально — платёжная логика, захват и
сведение дорожек, работа с БД и хранилищем, диалог входа аккаунта
(телефон → код → 2FA, включая неверный код/пароль и повторный ввод),
очередь заявок на смену профиля, изоляция параллельных записей на разных
воркерах — всё прогонялось напрямую (в т.ч. через синтетические
аудио/видео-потоки, мок-сервер S3 и мок Pyrogram-клиента для логина), без
обращения к реальному Telegram — живого звонка и реального SMS-кода это,
разумеется, не заменяет.

Честно о том, что стоит перепроверить перед реальным продакшеном:
- Синхронизация звука и видео в грид-рендере — best-effort (см.
  `userbot/recorder.py`), на нестабильном соединении возможен небольшой дрейф
- `datetime.utcnow()` используется во всей кодовой базе для единообразия;
  Python 3.12+ помечает его как deprecated (не ошибка, просто предупреждение) —
  при желании можно перевести на `datetime.now(timezone.utc)`
- Подписка Stars продаётся по цене тарифа «1 месяц»; отдельной цены на
  годовую Stars-подписку нет, так как Bot API поддерживает только
  фиксированный 30-дневный период подписки
- Промокоды дают дни Премиума напрямую, а не процентную скидку при оплате —
  так надёжнее и проще, но это осознанное упрощение, а не оговорка
